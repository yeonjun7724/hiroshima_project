# 발표 컨셉

## 바이브 코딩으로 이해하는 공간분석과 데이터 인사이트

이 발표는 히로시마의 교통지도를 보여주는 데서 끝나지 않는다. 자연어로 공간 질문을 만들고, 바이브 코딩으로 필요한 분석 기능을 빠르게 조합하고, 결과를 지도와 수치로 검증해 정책적 인사이트로 발전시키는 과정을 보여준다.

## 1. 출발점: 공간 질문 만들기

“정류장이 많은 지역이 정말 교통 접근성이 좋은가?”, “인구를 고려하면 어디가 비어 있는가?”, “직선거리와 실제 보행거리는 얼마나 다른가?”처럼 관찰 가능한 질문에서 시작한다. 질문이 명확해야 필요한 데이터와 공간분석 기능을 선택할 수 있다.

## 2. 바이브 코딩으로 분석 기능 탐색하기

바이브 코딩은 코드를 무비판적으로 생성하는 것이 아니다. AI에게 분석 의도를 자연어로 설명하고, GeoPandas·Folium·OSMnx·pydeck 같은 기능을 조합해 빠르게 실행한다. 이후 좌표계, 조인 결과, 지도 모양, 결측치와 예외를 직접 확인하며 코드를 고친다.

## 3. 기능이 인사이트로 바뀌는 과정

1. `GeoPandas + CRS + spatial join`: 원자료를 공간 단위별 분석 테이블로 만든다.
2. `buffer + overlay`: 정류장 주변 서비스 범위와 미도달 영역을 구분한다.
3. `OSMnx + shortest path`: 직선거리가 아닌 실제 보행 네트워크 접근성을 계산한다.
4. `Folium/pydeck + ranking`: 결과를 탐색 가능한 지도와 후보지 우선순위로 전달한다.

## 4. 히로시마 사례에서 읽는 인사이트

단순 정류장 수만 보면 공급이 충분해 보이는 지역도 인구 규모와 서비스 범위를 함께 보면 취약할 수 있다. 또 직선거리 기반 결과는 도로망·하천·철도 같은 장벽을 반영하지 못한다. 따라서 최종 후보지는 시설 수 하나가 아니라 인구, 미도달 면적, 보행거리, 기존 공급을 함께 고려해 해석한다.

## 5. 발표에서 강조할 검증 포인트

- CRS가 도 단위인지 미터 단위인지 확인한다.
- spatial join과 overlay 이후 행 수·면적·중복을 점검한다.
- 지도에서 수치 결과가 실제 공간 맥락과 일치하는지 본다.
- 네트워크 분석 실패와 데이터 누락을 숨기지 않고 기록한다.
- 결과를 다른 도시 데이터에 바꿔 끼워도 재현되는지 확인한다.

## 결론

공간분석에서 중요한 것은 특정 라이브러리의 문법을 암기하는 것이 아니다. 질문에 맞는 기능을 선택하고, 빠르게 시도하고, 공간적으로 검증하고, 데이터의 한계를 밝히면서 인사이트를 만드는 능력이다. 히로시마는 그 과정을 보여주는 사례이며, 최종 목표는 어디서든 다시 쓸 수 있는 분석 패턴이다.
